# Storage-layout snapshots

Generated by `forge inspect <Contract> storage-layout`.

These are committed artifacts that pin the storage layout of every
**upgradeable** contract in this repo. Any PR that touches such a contract
**must** regenerate the corresponding snapshot and the diff in the snapshot
must be human-reviewed before merge. Silent slot moves break every existing
beacon proxy and are a silent footgun otherwise.

## Regeneration

```bash
for c in AgentCollectionImpl AgentIdentityRegistry AgentReputationRegistry \
         AgentMemory AgentContextRegistry AgentX402Receiver; do
  forge inspect "$c" storage-layout > docs/storage-layouts/$c.json
done
```

## CI guard (recommended)

Add the following job to GitHub Actions; it fails if any snapshot is out of
date with `main`'s source:

```yaml
- name: Storage layout drift
  run: |
    set -e
    for c in AgentCollectionImpl AgentIdentityRegistry AgentReputationRegistry \
             AgentMemory AgentContextRegistry AgentX402Receiver; do
      forge inspect "$c" storage-layout > /tmp/$c.json
      diff -u docs/storage-layouts/$c.json /tmp/$c.json
    done
```

## Audit-time interpretation

- **Append-only is safe.** New slots at the end of an upgradeable contract's
  storage do NOT break existing proxies.
- **Reordering, type-resizing, or insertion in the middle is fatal.** If a
  PR diff shows any of these, the upgrade path is incompatible and every
  proxy must be re-deployed.
- **Library-linked contracts** (`AgentCollectionImpl` links
  `AgentCollectionRenderer` and `AgentCollectionEIP712`) are immune to
  library-side storage changes because libraries are stateless. Confirm in
  the snapshot that no slots are owned by the library.
